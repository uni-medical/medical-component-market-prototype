## 现场讲稿

### 0:00–0:35｜开场

今天展示的是医疗 AI 组件市场的网页原型。它的目标很直接：让研究者从一个研究方向出发，找到相关组件，快速了解组件能做什么、来自哪里，以及是否值得继续查看。

今天主要看页面的信息组织和使用感受，先不展开安装、执行和完整数据服务。

### 0:35–1:05｜浏览方式

我先从“浏览方式”进入。这里提供四个入口，分别适合不同的浏览习惯：精确比较、按领域发现、了解生态全貌，以及组织可复用组件。

大家可以把它理解成同一个市场的四个入口，而不是四个互相独立的产品。

### 1:05–1:45｜学术型登记册

第一个是学术型登记册。

它把组件名称、类型、仓库、License、Star、标签、更新时间和来源信息放在一起，适合做逐条比较和资料整理。

这个方向更强调清晰、完整和可核对，适合研究组内部查阅，也适合后续形成规范化的组件目录。

### 1:45–2:25｜领域图谱

第二个是领域图谱。

用户不需要一开始就知道组件名称，可以先从医疗研究、科学发现、Agent 基础设施或 MCP 集成等领域开始，再进入具体条目。

它更适合探索式使用：先确定研究问题，再寻找能够支持这个问题的工具和组件。

### 2:25–3:15｜生态展示市场

第三个是生态展示市场。

这个页面采用更完整的产品化视觉：深色背景、蓝色光晕、领域入口和代表组件卡片。它要传达的是，医疗 AI 组件不是零散的仓库，而是可以持续扩展、持续发现的生态。

页面仍然保留每条记录的类型、来源、Star、License、标签和详情链接。代表区域覆盖 Plugin、Skill、Tool、MCP Server 和 CLI 五种类型，并优先呈现医疗相关条目。

如果未来需要一个对外介绍的默认入口，我会优先考虑这个方向。

### 3:15–3:55｜组合工作台

第四个是组合工作台。

它关注的是组件的组织和复用。例如，未来可以把检索、数据处理、分析和结果整理相关的组件放进同一个研究集合。

当前页面只展示这种组织方式，不把它描述成已经完成的工作流编辑器，也不执行真实组件。

### 3:55–4:40｜讨论与下一步

今天希望大家重点判断三件事：

1. 用户第一次进入时，最需要先看到什么；
2. 哪个入口最适合作为默认首页；
3. 其他入口是否保留为补充浏览方式。

确定主入口以后，我们再统一视觉规范和字段层级，然后进入真实目录同步、搜索和筛选的开发。
